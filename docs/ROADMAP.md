# РАЗЛОМ — дорожная карта

## Сделано: вертикальный срез этапа 1 (+ частично 2 и 3)

- Мир 128×96×128 с детерминированной генерацией: рельеф, вода, пещеры, деревья, спавн-площадка.
- Строительство и добыча 9 типов блоков, хотбар, подсветка цели, запечённый свет и AO.
- **Физика разрушения:** несущая способность, обрушение конструкций, падающие обломки, кратеры, огонь по дереву, течение воды.
- **Мультиплеер по ссылке:** хост в потоке клиента, отдельный headless-сервер, `razlom://host:port/CODE`, снимки 20 Гц, история правок для поздних игроков.
- **Каталог и режимы:** «Песочница», «Последний выживший», каркас «Защиты базы»; смена режима на лету.
- Мобильный ввод: стик, тач-обзор, кнопки действий, масштабируемый интерфейс (`sensorLandscape`).
- Бандлы: Windows `.exe` (D3D11), Android `.apk` (GLES3, NativeActivity), Linux (OpenGL).
- 139 автотестов + бенчмарк бюджета кадра; CI собирает все три платформы.

## Этап 2 — выживание и мобильный релиз (6–10 недель)

| Задача | Почему важно | Подход |
|---|---|---|
| Здоровье от падений, голод, ресурсы | Без выживания нет долгой игры | Серверные правила в `GameMode`; сейчас уже есть здоровье и PvP |
| Крафт и инвентарь | Прогрессия | Сетки 3×3 + рецепты в данных, а не в коде |
| Мобы/угрозы (минимум) | Причина строить стены | 2–3 простых существа, физика разрушения их ломает |
| Аккаунты и облако миров | Мир не теряется при смене телефона | Лёгкий сервер: код-ссылка + токен, хранение истории правок |
| Ретранслятор и NAT-punch | Игра по ссылке через интернет | WebSocket-релей на 2 ГБ трафика/мес на мир; хост держит мир, релей только пересылает |
| Мобильная оптимизация | Слабые телефоны | 45 FPS на Snapdragon 6xx: LOD чанков, 4-битные световые объёмы, асинхронный мешинг |

## Этап 3 — редактор режимов и каталог (8–14 недель)

- **Редактор как данные, не код:** граф правил (событие → условие → действие), шаблоны «последний выживший», «гонка», «защита базы».
- **Библиотека блоков логики:** спавн игрока, условие (счётчик/время/блок), действие (урон, телепорт, выдать блок, включить зону).
- **Каталог:** публикация режима по коду, витрина, рейтинги, запуск в один тап; скачивание = те же seed + правки + граф правил.
- **Песочница проверки:** автор запускает режим локально и видит ошибки правил до публикации.
- **Критерий готовности:** новый игрок собирает режим «кто первый до вершины» за 5 минут без инструкции.

## Этап 4 — маркетплейс и монетизация (постоянно)

- Косметика: скины блоков, эффекты разрушения, анимации входа — не влияют на баланс.
- Подписка: +3 слота миров, приоритет режима в каталоге, приватные миры.
- Доля авторам: 50–70 % с продаж режимов, выплаты от порога; антифрод (накрутка запусков) — обязателен до запуска выплат.
- Никакого pay-to-win: урон, прочность и ресурсы одинаковы для всех.

## Технический долг и риски

| Риск/долг | Статус | План |
|---|---|---|
| Физика на мобильных | Зона 53×53, ≤420 блоков, ≤2 зоны за тик | Рабочий поток, инкрементальный расчёт по чанкам |
| Один поток симуляции | Хватает на 4–16 игроков | Разделение миров по потокам/процессам при росте |
| TCP вместо UDP | Просто и надёжно для правок | Квантизация снимков, при необходимости — UDP-канал для позиций |
| Нет античита | Проверка дистанции/скорости | Серверная симуляция игроков, лимиты действий |
| Нет шифрования | Код = доступ | TLS/токены при появлении аккаунтов |
| Metal/macOS | Собирается, не проверялся | CI-джоб на macOS + проверка шейдеров |
| Контент-конвейер | Мир-генератор в коде | Вынести блоки/рецепты/режимы в JSON, затем — в редактор |

## Метрики, по которым судим успех

- **Первые 10 секунд:** доля новичков, сломавших опору до первого выхода из мира (> 70 %).
- **Первая сессия:** 15+ минут, первая постройка (> 50 %).
- **Социальность:** доля миров, куда зашли по ссылке (> 40 %).
- **UGC:** доля игроков, открывших редактор (> 3 %), и режимов с 20+ запусками.
- **Техника:** 45+ FPS на бюджетном Android, старт в мир < 3 с, обрывов на игрока < 1 %.
